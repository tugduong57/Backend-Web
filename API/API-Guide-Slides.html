CHƯƠNG 8.1

API là gì?

API (Application Programming Interface) là một bộ quy tắc và giao thức cho phép các ứng dụng khác nhau giao tiếp với nhau.

Ví dụ thực tế:

  • ✅ Một ứng dụng React frontend gọi API để lấy danh sách bài viết
  • ✅ Một ứng dụng mobile gọi API để đăng nhập người dùng
  • ✅ Một dịch vụ bên thứ ba gọi API để lấy dữ liệu

Khác biệt giữa API và Web truyền thống:

Web Truyền Thống API
Trả về HTML Trả về JSON/XML
Hiển thị giao diện Cung cấp dữ liệu
Browser là client chính Bất kỳ ứng dụng nào có thể là client
CHƯƠNG 8.1

RESTful API

REST (Representational State Transfer) là một phong cách kiến trúc API dựa trên các nguyên tắc chuẩn.

4 Nguyên tắc REST:

Nguyên tắc Mô tả
Resource-based Mỗi tài nguyên (users, posts) được biểu diễn qua URL
HTTP Methods Sử dụng GET, POST, PUT, DELETE để chỉ định hành động
Stateless Mỗi request độc lập, không phụ thuộc vào request trước
Representation Dữ liệu được trả về ở định dạng JSON/XML

HTTP Methods trong RESTful:

  • GET: Lấy dữ liệu → GET /api/posts
  • POST: Tạo mới → POST /api/posts
  • PUT: Cập nhật toàn bộ → PUT /api/posts/1
  • DELETE: Xóa → DELETE /api/posts/1

CHƯƠNG 8.2

Định Tuyến API (api.php)

Trong Laravel, tất cả các route API được định nghĩa trong file routes/api.php

Khác biệt: routes/api.php vs routes/web.php

Đặc điểm api.php web.php
Session State ❌ Không có ✅ Có
Prefix mặc định /api Không có
CSRF Protection ❌ Không cần ✅ Có
Middleware api web
Return JSON HTML (View)

Ví dụ cấu trúc routes/api.php:

Route::middleware('api')->group(function () {
    Route::apiResource('posts', PostController::class);
    Route::apiResource('users', UserController::class);
    Route::post('posts/{post}/publish', [PostController::class, 'publish']);
});

apiResource vs resource

Laravel cung cấp hai helper để tạo routes một cách tự động:

Bảng so sánh chi tiết:

HTTP Method & Route apiResource resource Mục đích
GET /posts ✅ index() ✅ index() Lấy danh sách
GET /posts/create ❌ ✅ create() Form tạo mới
POST /posts ✅ store() ✅ store() Lưu dữ liệu mới
GET /posts/{id} ✅ show() ✅ show() Chi tiết resource
GET /posts/{id}/edit ❌ ✅ edit() Form chỉnh sửa
PUT /posts/{id} ✅ update() ✅ update() Cập nhật dữ liệu
DELETE /posts/{id} ✅ destroy() ✅ destroy() Xóa dữ liệu
💡 Quy tắc: Dùng apiResource cho API (không cần form HTML), dùng resource cho web truyền thống

API Controllers

API Controllers khác với Web Controllers ở những điểm chính:

Đặc điểm của API Controller:

  • ❌ Không trả về View (Blade template)
  • ✅ Trả về JSON response
  • ❌ Không xử lý HTTP session
  • ✅ Xử lý HTTP status codes rõ ràng
  • ✅ Xử lý lỗi theo chuẩn HTTP

Tạo API Controller:

php artisan make:controller Api/PostController --api
Kết quả: Tạo controller với 7 method cơ bản:
  • index() - Lấy danh sách
  • store() - Tạo mới
  • show() - Chi tiết
  • update() - Cập nhật
  • destroy() - Xóa
CHƯƠNG 8.3

Trả về JSON Response

Laravel cung cấp helper response()->json() để trả về JSON dễ dàng:

Cách sử dụng cơ bản:

// Cách 1: Đơn giản
return response()->json($data);

// Cách 2: Với status code
return response()->json($data, 200);

// Cách 3: Với headers
return response()->json($data, 200, [], JSON_UNESCAPED_UNICODE);

Ví dụ JSON Response thực tế:

return response()->json([
    'success' => true,
    'data' => [
        'id' => 1,
        'title' => 'Học Laravel API',
        'author' => 'Trần Văn A'
    ],
    'message' => 'Lấy dữ liệu thành công'
], 200);

Response nhận được:

{
    "success": true,
    "data": {
        "id": 1,
        "title": "Học Laravel API",
        "author": "Trần Văn A"
    },
    "message": "Lấy dữ liệu thành công"
}

Validation bằng FormRequest

FormRequest là một class để tập trung xác thực dữ liệu của request

Lợi ích FormRequest:

  • ✅ Tách biệt logic validation khỏi controller
  • ✅ Dễ tái sử dụng validation rules
  • ✅ Dễ bảo trì
  • ✅ Có thể tùy chỉnh response lỗi

Tạo FormRequest:

php artisan make:request StorePostRequest
php artisan make:request UpdatePostRequest

Sử dụng trong Controller:

public function store(StorePostRequest $request)
{
    // Dữ liệu đã được validate tự động
    $validated = $request->validated();
    
    $post = Post::create($validated);
    
    return response()->json([...], 201);
}

Các Validation Rules phổ biến

Rule Mô tả Ví dụ
required Trường bắt buộc 'name' => 'required'
string Phải là string 'title' => 'string'
integer Phải là số nguyên 'age' => 'integer'
email Phải là email hợp lệ 'email' => 'email'
min:value Độ dài tối thiểu 'password' => 'min:8'
max:value Độ dài tối đa 'name' => 'max:255'
unique:table,column Phải unique trong DB 'email' => 'unique:users'
exists:table,column Phải tồn tại trong DB 'user_id' => 'exists:users,id'
in:val1,val2 Phải là một trong các giá trị 'status' => 'in:draft,published'

Ví dụ kết hợp multiple rules:

'email' => 'required|email|unique:users,email',
'password' => 'required|string|min:8|confirmed',
'age' => 'required|integer|min:18|max:120'

CHƯƠNG 10.3

HTTP Status Codes

HTTP status codes cho biết kết quả của request API:

Status Codes phổ biến:

Code Ý nghĩa Sử dụng
200 OK GET, PUT, PATCH thành công
201 Created POST tạo resource mới thành công
204 No Content DELETE thành công (không có response body)
400 Bad Request Request không hợp lệ
401 Unauthorized Không xác thực hoặc token không hợp lệ
403 Forbidden Không có quyền truy cập
404 Not Found Resource không tồn tại
422 Unprocessable Entity Validation failed
500 Server Error Lỗi ở server

CHƯƠNG 11.1

Stateful vs Stateless Authentication

Stateful (Session-based):

  • 📌 Server lưu trữ session của user
  • 🔄 Client gửi session ID trong mỗi request
  • ❌ Khó mở rộng (khó scale horizontally)
  • 🕐 Session có thể timeout
  • ✅ Phù hợp: Web truyền thống

Stateless (Token-based):

  • 📭 Server không lưu trữ state
  • 🔑 Client gửi token trong Authorization header
  • ✅ Dễ mở rộng (dễ scale horizontally)
  • ⏰ Token có thời gian hết hạn
  • ✅ Phù hợp: API, Mobile, SPA

Bảng so sánh:

Đặc điểm Stateful Stateless
Server State Lưu session Không lưu
Scalability Khó mở rộng Dễ mở rộng
Storage Server/DB Client
Transmission Cookie Header (Authorization)
CHƯƠNG 11.2

Laravel Sanctum

Laravel Sanctum là package bảo mật chính thức của Laravel cho API authentication

Sanctum cho phép bạn:

  • ✅ Cấp API tokens cho users
  • ✅ Xác thực stateless API requests
  • ✅ Bảo vệ routes bằng middleware
  • ✅ Quản lý token expiration
  • ✅ Tạo personal access tokens

Cài đặt Sanctum:

# Cài đặt package
composer require laravel/sanctum

# Publish migrations
php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"

# Chạy migrations
php artisan migrate

Cấu hình trong Model:

namespace App\Models;

use Laravel\Sanctum\HasApiTokens;

class User extends Model
{
    use HasApiTokens;
}
💡 Kết quả: Tạo bảng personal_access_tokens để lưu trữ tokens

Authentication Flow

1️⃣ Đăng ký (Register):

POST /api/auth/register
{
    "name": "Trần Văn A",
    "email": "tranan@example.com",
    "password": "password123",
    "password_confirmation": "password123"
}

2️⃣ Đăng nhập (Login):

POST /api/auth/login
{
    "email": "tranan@example.com",
    "password": "password123"
}

Response: {
    "token": "1|abcdefghijklmnopqrstuvwxyz..."
}

3️⃣ Sử dụng Token:

GET /api/posts
Authorization: Bearer 1|abcdefghijklmnopqrstuvwxyz...

4️⃣ Đăng xuất (Logout):

POST /api/auth/logout
Authorization: Bearer 1|abcdefghijklmnopqrstuvwxyz...
💡 Quy trình: Register → Login (nhận token) → Dùng token → Logout
CHƯƠNG 12.1

CORS (Cross-Origin Resource Sharing)

CORS là cơ chế bảo mật của trình duyệt kiểm soát cross-origin requests

Vấn đề CORS:

Frontend: http://localhost:3000
Backend API: http://localhost:8000

👉 Trình duyệt sẽ chặn request vì domain/port khác!

Quy trình CORS:

  1. Browser gửi Preflight Request (OPTIONS)
  2. Server trả về CORS headers xác nhận
  3. Nếu được phép → Browser gửi Actual Request
  4. Nếu không → Browser chặn request

Cấu hình CORS trong Laravel:

// config/cors.php
return [
    'paths' => ['api/*'],
    'allowed_origins' => [
        'http://localhost:3000',
        'http://localhost:5173',
        'https://example.com'
    ],
    'allowed_methods' => ['*'],
    'allowed_headers' => ['*']
];

Ví dụ Fetch API (Vanilla JavaScript):

1. Lấy danh sách bài viết:

fetch('http://localhost:8000/api/posts')
    .then(response => response.json())
    .then(data => {
        console.log(data.data);
        displayPosts(data.data);
    })
    .catch(error => console.error('Error:', error));

2. Tạo bài viết mới:

fetch('http://localhost:8000/api/posts', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'Authorization': 'Bearer ' + token
    },
    body: JSON.stringify({
        title: 'Bài viết mới',
        content: 'Nội dung...',
        user_id: 1
    })
})
.then(response => response.json())
.then(data => console.log(data));

3. Xóa bài viết:

fetch(`http://localhost:8000/api/posts/${id}`, {
    method: 'DELETE',
    headers: {
        'Authorization': 'Bearer ' + token
    }
});

Best Practices

🔐 1. Security (Bảo mật)

  • ✅ Luôn validate input từ client
  • ✅ Sử dụng HTTPS trong production
  • ✅ Không expose sensitive data (passwords, tokens)
  • ✅ Sử dụng rate limiting để ngăn brute force

📋 2. Response Format (Format Response)

  • ✅ Consistent response structure
  • ✅ Bao gồm success flag, data, message
  • ✅ Proper HTTP status codes

📝 3. Error Handling (Xử lý lỗi)

  • ✅ Meaningful error messages
  • ✅ Validation errors chi tiết
  • ✅ Log errors trên server

🚀 4. Performance (Hiệu suất)

  • ✅ Implement pagination cho danh sách lớn
  • ✅ Eager loading để tránh N+1 queries
  • ✅ Caching khi cần thiết

📚 5. Naming Conventions (Đặt tên)

  • ✅ Routes: kebab-case (/api/posts)
  • ✅ Methods: camelCase (getPosts)
  • ✅ Database: snake_case (user_profiles)

API Development Workflow

Quy trình phát triển API:

1. DESIGN API

  • 📋 Định nghĩa endpoints
  • 📋 Xác định HTTP methods
  • 📋 Thiết kế response format

2. IMPLEMENT BACKEND

  • 💾 Tạo routes (routes/api.php)
  • 💾 Tạo API Controllers
  • 💾 Tạo FormRequests để validation
  • 💾 Tạo API Resources để format response

3. IMPLEMENT AUTHENTICATION

  • 🔐 Tạo Auth Controller (register, login, logout)
  • 🔐 Cấu hình Sanctum tokens
  • 🔐 Bảo vệ routes với middleware

4. TEST API

  • ✅ Kiểm thử endpoints bằng Postman
  • ✅ Kiểm thử validation
  • ✅ Kiểm thử authentication

5. CONFIGURE CORS

  • 🌐 Cấu hình allowed origins
  • 🌐 Cấu hình allowed methods
  • 🌐 Cấu hình allowed headers

6. INTEGRATE FRONTEND

  • 🎨 Implement Fetch API / Axios
  • 🎨 Xử lý requests và responses
  • 🎨 Lưu tokens
  • 🎨 Hiển thị dữ liệu
